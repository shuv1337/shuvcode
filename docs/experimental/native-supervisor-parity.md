# Native supervisor: ShuvBro parity

The native implementation covers the orchestration and runtime portion of the intended ShuvBro workflow through Shuvcode Sessions, a durable supervisor, and native tools. Full parity also requires first-class Herdr support for the lead, workers, and secondmates. The [three-repository contract and local evidence](native-supervisor-herdr.md) cover the new managed-home integration; companion review and two-host qualification remain open. Compatibility with other agent harnesses and multiplexers is outside this native path.

This is an experimental implementation with qualified local and isolated-box behavior. Herdr qualification, production migration, and live external integrations require the additional checks below.

The comparison is pinned to ShuvBro `b952627653ee2e0a9df5224b4678e7d2d7a5a70d` and Shuvcode base `28350a1f141e1fe7fef440d72ca791d31f595349`. Development is on `native-supervisor`. Verification below was completed October 5, 2026, PDT. No package has been published.

## Completed verification

- `bun test test/supervisor-*.test.ts` from `packages/cli`: **169 passed, 0 failed**, 1,177 assertions across 27 files.
- Core Session execution/recovery suite: **37 passed**, 180 assertions, including cancelled roots and nested background children remaining stopped while unrelated claimed Sessions recover.
- Existing server process and CLI web UI tests: **4 passed**, 212 assertions.
- Canonical `bun run check`: **41/41 tasks passed**. Scoped formatting and `git diff --check` passed.
- The installed Linux CLI completed the first-request knowledge and managed restart smoke, with **17 assertions**, and the packed offline npm install smoke. No package was published.
- The actual ship task's five Bun tests passed independently on the VM after local landing.

The active-work crash test exposed that private stdio servers had never enabled native restart recovery. Managed startup now waits for the supervisor tool bridge before releasing native recovery. A second crash-window test exposed that a durable cancellation could resume one extra model request; recovery now terminalizes cancelled roots and their background descendants before resuming other claims. The public idle interruption behavior and ordinary managed-service recovery path remain unchanged.

## Remaining production qualification

Run an explicitly authorized live forge/no-mistakes workflow, configured Relay delivery, and actual speech/device checks before relying on those integrations. Qualify remote placement across two separate hosts. Measure idle CPU/RSS, multi-worker latency, task quality, intervention rate, and token cost against the same ShuvBro tasks and model before claiming better speed, cost, or production readiness.

Evidence freshness is enforced as a changed supplied evidence value; the supervisor does not independently verify whether the fact is true. Unreachable or over-budget delegates remain unresolved until curation, an operator budget change, or an explicit retry. Legacy shared caches without UUID ownership require reconciliation.

Managed mode fences the native process it owns before clearing uncertain admission. External-server mode cannot supply that ownership guarantee and retains uncertainty as a blocker. Production ShuvBro services were not changed.

## SEP-2640 MCP Skills

Upstream `df79010bc6` is taken verbatim in `packages/core/src/plugin/mcp-skill.ts`. Enable with `experimental.mcp_skills: true` or `OPENCODE_FLAGS=mcp_skills`; it defaults off in release and `integration-v2` builds (on in local/dev builds unless disabled). Skills are listed without reading files; static files are verified by size and digest when used.

| Transport       | Read-only verification                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Stdio           | A local entry uses `executor mcp --host https://<executor-host>` against the self-hosted Executor instance. A signed-in SDK probe via that bridge negotiated `2025-11-25`, listed 49 valid static skills and received 2,552 characters of instructions. The bridge reuses the Executor CLI sign-in.                                                                                                                                                                                                                                                                                                                                                        |
| Streamable HTTP | Unauthenticated `initialize` at `https://<executor-host>/mcp` returned `401` with a `Bearer` challenge and protected-resource metadata URL, including with Shuvcode's `?codemode=false` query. Discovery returned `200`, and the same SDK Shuvcode uses resolved the authorization server, authorization-code grant, PKCE `S256` and dynamic client registration. Shuvcode's remote transport supports both the OAuth provider and configured HTTP headers. The bridge is not required by the protocol; direct use needs its own authorized OAuth session or a valid bearer for this resource. No direct sign-in or authenticated HTTP call was performed. |

`McpClient` builds one SDK initialization path shared by spawned stdio and Streamable HTTP. With the flag enabled both advertise `extensions["io.modelcontextprotocol/skills"] = {}`. The local transport passes the spawned stream to it; the remote transport passes `StreamableHTTPClientTransport`. The upstream regression test also asserts the declaration on the HTTP wire against a local test server.

Keep the flag off for Executor until these follow-ups are addressed:

1. **Name collisions.** 24 of 49 offered skills have `frontmatter.name: "tools"`. The `<server>:<name>` registry accepts the first and silently drops the other 23, so only 26 register. Give Executor skills distinct names aligned with the URI's last segment; consider logging collisions rather than silently skipping.
2. **Instructions suppression.** Once at least one static skill is present, the server's MCP instructions are omitted from the prompt. Executor's 2,552-character instructions therefore disappear; the agent must load the Executor skill to get that guidance.
3. **Modern caching metadata.** On `2026-07-28`, the SDK requires `ttlMs` and `cacheScope` on `skills/list`. Missing either can make the catalog empty after a failed listing. The observed bridge uses `2025-11-25`, so this does not affect that probe.

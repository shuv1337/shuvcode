## Tool and automation alignment

Per Lauren's call (Nov 23), the fork follows upstream for every tool and automation change:

- **Automation tools** use upstream's own `automation` namespace (`tools.automation.create`, `.list`, `.pause`, `.resume`, `.delete`). `automation.ts` and `automation.txt` match upstream exactly.
- **Unattended denylist.** The fork takes upstream's shorter list (#65217). This loosens the previous fork restriction per Lauren's call (Nov 23). Automation code may now call `shell`, `session.rename` and the worktree tools; only automation management and `session.move` stay blocked. Upstream's `automation-shell` capability test passes. The only difference from upstream's `automation/code.ts` is the fork's tool ID `shuvcode.session.move`. `automation.test.ts` adds five lines that assert that denial.
- **Automation shell timeout.** Upstream's `e1fb08afc5` (stop a timed-out automation shell command instead of backgrounding it) merged cleanly. The fork's shell files match upstream.
- **Remaining tool differences** are fork identity or fork-only features, and are kept:
  - Identity: the `shuvcode` tool namespace and `shuvcode.session`, the `Shuvcode` descriptions, and the `opencode_*` MCP permission action names.
  - Fork-only features: rich tool errors (`adoptToolError`, `settleFailure`, the `ToolActivity` lease), `glob`/`grep` metadata filtering, subagent root-family routing (#429), the built-in plugin `options` passthrough and `shuvcode.*` plugin targets in `PluginSupervisor`, and the `jev_systemOne` tool. Upstream ships no equivalent for any of them.
- **Partial overlap, kept.** Upstream's core now ships GPT-Live voice (`packages/core/src/voice.ts`). It needs an OpenAI API key or an OpenCode Console connection, and says ChatGPT sign-in can't start voice sessions. The fork's built-in `@shuvcode/gpt-live-plugin` runs GPT-Live on a ChatGPT subscription. That is not equivalent, so the plugin stays. Cap may want to review whether both should be offered.

## Install

<Callout type="note">The curl install script is not available in beta.</Callout>

You can also install it with the following package managers.

<Tabs>
  <Tab title="npm">
    ```bash
    npm install -g shuvcode@next
    ```
  </Tab>
  <Tab title="bun">
    ```bash
    bun install -g --trust shuvcode@next
    ```
  </Tab>
  <Tab title="pnpm">
    ```bash
    pnpm add -g --allow-build=shuvcode shuvcode@next
    ```
  </Tab>
  <Tab title="Yarn">
    ```bash
    yarn global add shuvcode@next
    ```
  </Tab>
</Tabs>

The package uses a trusted postinstall script to select the native binary for your platform. The Bun and pnpm commands
above explicitly allow that script to run.

<Callout type="note">The binary is called `shuvcode`.</Callout>

#### Prerequisites

To use Shuvcode in your terminal, you'll need:

1. A modern terminal emulator like:
   - [Ghostty](https://ghostty.org), Linux and macOS
   - [WezTerm](https://wezterm.org), cross-platform
   - [Alacritty](https://alacritty.org), cross-platform
   - [Kitty](https://sw.kovidgoyal.net/kitty/), Linux and macOS
2. API keys for the LLM providers you want to use.

## Connect

With Shuvcode you can use any LLM provider by configuring its API key.

Run `/connect` in the TUI and select your provider.

```text
/connect
```

Use `/models` to browse the providers and models available to your project. See [Providers](/providers) for connection and
configuration details.

## Usage

You are now ready to use Shuvcode in your project. Here are a few common workflows.

### Ask questions

Ask Shuvcode to explain your codebase.

<Callout type="tip">Use `@` to fuzzy search for files in the project.</Callout>

```text
How is authentication handled in @packages/functions/src/api/index.ts
```

### Add features

Ask Shuvcode to add a feature by describing the desired behavior and providing relevant context.

```text
When a user deletes a note, flag it as deleted in the database.
Create a screen that shows recently deleted notes.
From this screen, the user can restore a note or permanently delete it.
```

<Callout type="tip">Give Shuvcode plenty of context and examples.</Callout>

### Undo changes

Use `/undo` when a change isn't what you wanted.

```text
/undo
```

Shuvcode stages a conversation revert and restores your original message so you can revise it. In a Git repository, it
also restores file changes when snapshots were captured successfully. Run `/undo` multiple times to move the conversation
boundary back, or use `/redo` to restore the staged conversation and files. See [Undo](/snapshots) for
limitations and safety details.

```text
/redo
```
